# Taylor's Streamlit frontend

Run these commands from the repository root with Python installed:

```powershell
python -m pip install -r frontend/requirements.txt
python -m streamlit run frontend/app.py
```

The live app reuses the existing style helpers and CSS. It provides question submission,
loading states, session conversation history, source links, refusal display, connection
errors, retry, reset, and conversation download. No answers or collection statistics
are fabricated when the backend is unavailable.

## API handoff to Wilson

No backend exists on main yet. This is a **proposed contract** to coordinate with Wilson,
using the response shape already documented in the team's style guide.
The endpoint defaults to `http://localhost:8000/ask`; change it in the sidebar or set
`FIELDDEX_API_URL` before launching Streamlit.

Request: `POST` JSON with `{"question": "What are Pikachu's abilities?", "top_k": 4}`.

Expected response:

```json
{
  "kind": "answer",
  "text": "An answer generated by the backend from retrieved records.",
  "sources": [
    {"title": "Pikachu", "section": "Abilities", "url": "https://example.com/pikachu"}
  ]
}
```

`kind` is optional (defaults to `answer`), or `refusal` for unsupported questions.
`sources` is optional. The frontend preserves backend refusal wording. Each request
has a 60-second timeout and is an independent question; local history is not sent as
conversation context. Update `api_client.py` once Wilson confirms the API contract.

The existing `style_demo.py` remains a separate canned style preview. The live app
does not implement ingestion, chunking, embeddings, retrieval, guardrails, or API routes.
Data upload and general-chat modes are deferred until their backend contracts exist.
